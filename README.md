# บาลีทีละนิด

เว็บเรียนบาลีภาษาไทยสำหรับผู้เริ่มต้น: 3 บทเรียน แบบฝึกหัด ประวัติรายบัญชี และบททบทวนที่เลือกจากคะแนนล่าสุด รองรับ GitHub Pages โดยไม่ต้องมีเซิร์ฟเวอร์ Node.js ใน production

## ระบบและค่าใช้จ่าย

- **GitHub Pages**: หน้าเว็บ static สำหรับ repository สาธารณะ ใช้แผนฟรีได้
- **Supabase Free**: PostgreSQL สำหรับประวัติ และ Supabase Auth สำหรับบัญชี/รหัสผ่าน ภายใต้โควตาแผนฟรี ตรวจเงื่อนไขปัจจุบันที่ https://supabase.com/pricing โครงการฟรีอาจถูกพักเมื่อไม่มีการใช้งาน และบริการอีเมลเริ่มต้นมีข้อจำกัด อาจต้องตั้ง SMTP ของคุณหากมีผู้ใช้มากขึ้น
- **ChatGPT**: ผู้เรียนคัดลอกบริบทไปใช้ใน ChatGPT ด้วยบัญชีของตนเอง เว็บไม่เข้าถึงโควตา Plus และไม่เรียก OpenAI API ผลการสนทนาไม่ถูกบันทึกกลับมายังเว็บ
- การปรับบทเรียนใช้กติกาจากคะแนน ไม่ใช่ AI: ทบทวนบทที่คะแนนล่าสุดต่ำกว่า 80% ก่อน จากนั้นเลือกบทที่ยังไม่เรียน หรือบทที่ฝึกน้อยที่สุด

ไม่มี secret key ฝังในหน้าเว็บ ใช้ publishable key สาธารณะและ Row Level Security ผู้เรียนอ่านได้เฉพาะโปรไฟล์และประวัติของตัวเอง ผู้ดูแล Supabase ยังมีสิทธิ์เข้าถึงข้อมูลตามบทบาทผู้ดูแล

## ทดลองในเครื่อง

ใช้ Node.js 24 ขึ้นไป ไม่ต้องติดตั้ง dependency

```sh
cd /workspace/fun-pali-learning
npm test
npm start
```

พอร์ตเริ่มต้น 4173 หรือกำหนด `PORT` ได้ โหมดทดลองทำงานโดยไม่ต้องมี Supabase และเก็บประวัติในเบราว์เซอร์เครื่องนั้นเท่านั้น โหมดทดลองไม่ใช่บัญชีออนไลน์ ไม่ควรใช้เพื่อเก็บประวัติสำคัญ

## ตั้งค่า Supabase ครั้งแรก

1. เข้าสู่ https://supabase.com/dashboard ด้วย GitHub สร้างองค์กร **Free** และ New Project เลือกภูมิภาคใกล้ผู้เรียน เช่น Singapore ตั้งรหัสผ่านฐานข้อมูลที่รัดกุม เก็บไว้ส่วนตัว ไม่ใส่ใน repository หรือแชต
2. เมื่อโครงการพร้อม เปิด **SQL Editor → New query** คัดลอกเนื้อหาทั้งหมดของ `supabase/schema.sql` แล้วกด **Run** สคริปต์รันซ้ำได้และไม่ลบประวัติเดิม
3. เปิดหน้าการเชื่อมต่อโครงการ/การตั้งค่า API เพื่อหา **Project URL** และ **publishable key** (`sb_publishable_...`) หรือ legacy **anon** key หากโครงการใช้รูปแบบเก่า ห้ามใช้ `service_role`, `sb_secret_...` หรือ database password
4. ใส่สองค่าลงใน `config.js`:

   ```js
   export const config = {
     supabaseUrl: 'https://YOUR_PROJECT_REF.supabase.co',
     supabasePublishableKey: 'YOUR_PUBLIC_PUBLISHABLE_KEY'
   };
   ```

5. เปิด **Authentication → URL Configuration** ตั้ง **Site URL** เป็น `https://jirayudech.github.io/fun-pali-learning/` และเพิ่ม URL เดียวกันใน **Redirect URLs** หากทดลองในเครื่องให้เพิ่ม URL ของเครื่องพัฒนาแยกด้วย ไม่ใช้ wildcard กว้างใน production
6. เปิดการสมัครผ่าน Email ใน **Authentication → Providers / Sign In** และเปิด **Confirm email** ตรวจอีเมลยืนยันการสมัคร บริการส่งอีเมลเริ่มต้นของ Supabase มีข้อจำกัดตามแผนปัจจุบัน หากส่งให้เพื่อนไม่ได้ให้ตั้ง custom SMTP ที่ตรวจสอบแล้วใน Authentication ก่อนเปิดรับผู้ใช้ทั่วไป ห้ามใส่รหัสผ่าน SMTP ลงในเว็บ
7. สมัครบัญชีทดสอบสองบัญชี ทำแบบฝึกหัดด้วยบัญชีแรก แล้วตรวจว่าบัญชีที่สองไม่เห็นประวัติแรก ปิดและเปิดเบราว์เซอร์ใหม่ด้วยบัญชีแรกเพื่อตรวจว่าประวัติยังอยู่

บัญชี Supabase Dashboard เป็นของผู้ดูแลเว็บ เพื่อนสมัครผ่านหน้าเว็บได้โดยไม่ต้องมีบัญชี Dashboard การเข้าสู่ Dashboard ด้วย ChatGPT ไม่ได้ให้เว็บใช้โควตา ChatGPT Plus

## เผยแพร่ GitHub Pages

1. ต้องเป็น repository สาธารณะสำหรับ GitHub Free และคุณต้องมีสิทธิ์จัดการ repository
2. Commit และ push โค้ดนี้รวม `config.js` ที่มีเฉพาะข้อมูลสาธารณะ ไปยัง `main`
3. ใน GitHub เปิด **Settings → Pages → Build and deployment → Source: GitHub Actions**
4. เปิด **Actions → Publish learning website → Run workflow** หรือ push อีกครั้งเพื่อเริ่ม deployment
5. รอ workflow ผ่านทั้ง build และ deploy แล้วเปิด URL ที่ GitHub แสดง โดย URL ที่คาดหมายคือ `https://jirayudech.github.io/fun-pali-learning/` URL นี้ยังไม่ยืนยันว่ามีเว็บจนกว่า deployment จะสำเร็จ
6. ตรวจทั้งหน้าเว็บ สมัคร/ยืนยันอีเมล/เข้าสู่ระบบ บันทึกผล อ่านประวัติ และออกจากระบบ ก่อนส่งลิงก์ให้เพื่อน

Workflow ส่งเฉพาะ `index.html`, `app.js`, `style.css`, `config.js`, `lessons.js`, `favicon.svg` ไม่ส่ง SQL หรือไฟล์ทดสอบขึ้นหน้าเว็บ การไม่มีค่า Supabase จะแสดงโหมดทดลองอย่างชัดเจนและปิดการสร้างบัญชี

## ฐานข้อมูลและสิทธิ์

- `profiles`: ชื่อที่แสดง เชื่อมกับ `auth.users` (รหัสผ่านอยู่ในระบบ Auth)
- `attempts`: บทเรียน คะแนน จำนวนข้อ และเวลา ไม่มีข้อความแชต ChatGPT
- `question_bank`: คำถามและเฉลยสำหรับตรวจบนฐานข้อมูล ปิดการอ่านผ่าน REST ของผู้เรียน
- `quiz_sessions`: แบบฝึกหัดที่ออกให้บัญชีนั้น อายุ 1 ชั่วโมง ส่งได้ครั้งเดียว
- `start_quiz` และ `submit_quiz`: RPC ใช้ผู้ใช้จาก JWT ตรวจสิทธิ์ ตรวจคำตอบ และบันทึกคะแนน ไม่รับคะแนนจาก client

เฉลยตัวอย่างใน `lessons.js` ใช้โหมดทดลองและอาจอ่านได้ใน source การทดสอบนี้มีไว้ฝึกเรียน ไม่ใช่ระบบสอบแข่งขัน บัญชีจริงยังตรวจคะแนนใน PostgreSQL

ประวัติบน dashboard แสดงไม่เกิน 1,000 ครั้งล่าสุด ประวัติเก่ากว่านั้นยังอยู่ในฐานข้อมูล โหมดทดลองเก็บประวัติใน localStorage ล้างได้ผ่านการล้างข้อมูลไซต์ บัญชีจริงเก็บ session token ใน localStorage ของเบราว์เซอร์; ใช้ออกจากระบบเมื่อใช้เครื่องร่วมกับผู้อื่น หน้าเว็บไม่มีสคริปต์ third-party

เวอร์ชันแรกยังไม่มีหน้าเปลี่ยน/กู้รหัสผ่านหรือลบบัญชีด้วยตนเอง ผู้ดูแลจัดการคำขอลบบัญชีใน Supabase Auth ได้ การลบบัญชีจะลบโปรไฟล์และประวัติที่ผูกไว้ด้วย `ON DELETE CASCADE` สำรองข้อมูลและทดสอบการกู้คืนก่อนใช้งานจริงระยะยาว
