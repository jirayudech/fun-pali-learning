# บาลีทีละนิด

เว็บเรียนบาลีภาษาไทยสำหรับผู้เริ่มต้น: 9 บทเรียน แบบฝึกหัด เกมไวยากรณ์ 6 ด่าน (30 โจทย์) ประวัติรายบัญชี และบททบทวนที่เลือกจากคะแนนล่าสุด รองรับ GitHub Pages โดยไม่ต้องมีเซิร์ฟเวอร์ Node.js ใน production

## เปิดเกมและ leaderboard ในโครงการที่มีอยู่

ใน Supabase SQL Editor รันไฟล์ **`supabase/games.sql` ทั้งหมด** หลังจากเคยรัน `schema.sql` แล้ว สคริปต์นี้เพิ่มตารางเกม ฟังก์ชันตรวจคำตอบ บันทึก XP และอันดับ โดยเก็บบัญชีและประวัติเดิมไว้ รันซ้ำได้ สำหรับโครงการใหม่ให้รัน `schema.sql` ก่อน `games.sql` ตามลำดับ ไม่ต้องส่ง database password หรือ service role key มาในแชต

ถ้าระบบเกมออนไลน์ยังไม่พร้อม ปุ่มเล่นจะเปิดการฝึกในเครื่องพร้อมข้อความระบุชัด โดยคงการเข้าสู่ระบบเดิมไว้ XP ฝึกในเครื่องแยกเก็บตามบัญชีใน localStorage ไม่ส่งคะแนนหรือ XP ไปยังประวัติออนไลน์หรือ leaderboard และไม่เปลี่ยนผู้ใช้เป็นบัญชีทดลอง เมื่อกดเริ่มเกมใหม่จะตรวจการพร้อมใช้งานอีกครั้ง หลังรัน migration สำเร็จจึงกลับไปใช้การตรวจคะแนนบนฐานข้อมูลได้ตามเดิม

ผลจบด่านฝึกในเครื่องจะเก็บด้วยและแสดงป้าย “จบด่านแล้ว · ในเครื่อง” รวมถึงในหน้าประวัติ ข้อมูลยังอยู่เมื่อรีโหลด แต่ไม่ซิงก์ข้ามอุปกรณ์หรือขึ้นอันดับ ข้อมูลเก่าที่มีเพียง XP ใช้แสดง “เคยฝึกในเครื่อง” ไม่สร้างคะแนนหรือผลจบด่านย้อนหลังที่ไม่มีหลักฐาน หน้าอันดับระบุเหตุผลเมื่อปุ่มบันทึกใช้งานไม่ได้ และตรวจความพร้อมซ้ำได้โดยคงชื่อกับตัวเลือกการเข้าร่วมไว้

ศัพท์สอบทยอยสอนครั้งละคำ เช่น “อการันต์ = รูปฐานลงท้ายเสียงอะ” มีตัวอย่างและการ์ดอธิบายก่อนโจทย์ที่ใช้ศัพท์นั้น และทวนในบทถัดไป ข้อความเก่าจากฐานข้อมูลที่ใช้ a-stem จะแสดงด้วยศัพท์อการันต์โดยอัตโนมัติ จึงไม่จำเป็นต้องแก้ฐานข้อมูลเฉพาะเพื่อเปลี่ยนคำแสดงผลนี้

เกมมีเลือกคำ เติมรูปศัพท์ เรียงคำตามรูปแบบที่กำหนด และจับคู่ ให้ผลทันทีพร้อมคำอธิบาย ข้อที่ผิดวนกลับมาทวนอีกไม่เกิน 2 ครั้ง คะแนนบทเรียนคิดจากคำตอบครั้งแรก ส่วน XP ให้กับคำตอบถูกหลังทวนด้วย แต่ให้ได้เพียง **10 XP ต่อโจทย์ต่อวันตามเวลา Asia/Bangkok** ด่านและคะแนนตรวจใน PostgreSQL ส่งซ้ำข้อเดิมหรือเกมของคนอื่นไม่ได้ ชุดโจทย์ใช้ฝึก ไม่ใช่ข้อสอบแข่งขันที่ปิดเฉลยทั้งหมด เนื่องจากโหมดทดลองมีเฉลยใน source

อันดับประจำสัปดาห์เริ่มวันจันทร์ตามเวลาไทย แสดง 20 คนแรกและอันดับของผู้ใช้เอง ผู้เรียนต้องเลือกเข้าร่วมและตั้งชื่อเล่นก่อน เผยเฉพาะชื่อเล่นและ XP ให้ผู้ใช้ที่เข้าสู่ระบบ ไม่มีอีเมล UUID หรือประวัติรายข้อในผล RPC ถอนตัวแล้วจะไม่อยู่ในผลอันดับ คะแนนเท่ากันได้อันดับเดียวกัน โหมดทดลองไม่ถูกส่งขึ้นอันดับและไม่สร้างผู้เล่นสมมติ

เนื้อหาไวยากรณ์และโจทย์รอบนี้เขียนใหม่: นามและหน้าที่ วิภัตติ วจนะ กริยาปัจจุบัน สรรพนาม และการอ่านประโยค เว็บแนะนำอ่านต่อคือ https://thunder.purivaro.com/ แต่ยังไม่ได้ตรวจเทียบหรือคัดลอกบทเรียนจากเว็บนั้น เพราะเครื่องพัฒนาถูกเครือข่ายบล็อก จึงไม่ควรอ้างว่าเนื้อหานี้นำมาจากบาลีธันเดอร์

## ภาพประกอบเวกเตอร์

ภาพใน `assets/*.svg` เป็นเวกเตอร์วาดใหม่ 15 ภาพ: น้องช้างใบลาน สวน ถ้วยรางวัล ฉากประจำบทเรียนทั้ง 9 บท ภาพเพื่อนนักเรียน ภาพตอบถูก และภาพชวนคิด ใช้บนหน้าเข้าสู่ระบบ หน้าเรียน หน้าด่าน โจทย์ feedback และ leaderboard โหลดจากไฟล์ภายในเว็บ ไม่ต้องมี API key หรือเครดิตสร้างภาพ ภาพประกอบทั่วไปใช้ alt ว่างเพื่อให้ screen reader เน้นเนื้อหา และ animation รองรับ reduced motion

สร้างภาพประจำบทและภาพเพื่อนด้วย `node scripts/draw-vectors.js` แก้โครงสร้าง SVG ได้โดยตรงหรือแก้ในสคริปต์ก่อนสร้างซ้ำ `art.js` กำหนดเส้นทางภาพ เวอร์ชันนี้เลือกใช้เวกเตอร์ต่อและไม่จำเป็นต้องใช้ Pollinations

## อักษรบาลีไทยและเป้าหมายสอบ

ใช้ `pali-script.js` แสดงรูปบาลีอักษรไทยเป็นหลักและโรมันกำกับ ทั้งข้อความที่มาจาก Supabase เดิมและเกมใหม่ โดยใช้พจนานุกรมรูปที่ตรวจไว้สำหรับคำในคอร์ส ไม่ใช่ตัวแปลงโรมันอัตโนมัติสำหรับคำทั้งหมด ไม่เปลี่ยนลำดับตัวเลือกหรือดัชนีคำตอบ และไม่ต้องรัน SQL เพิ่มเพื่อแสดงอักษรไทย

เป้าหมายที่ผู้ใช้แจ้งคือสอบบาลีสนามหลวง 3–4 มีนาคม 2570; ยังไม่ได้ตรวจยืนยันกำหนดการทางการ ผู้ใช้ยืนยันระดับประโยค 1–2 เน้นไวยากรณ์พื้นฐาน การแยกศัพท์ และการแปลบาลีเป็นไทย ดู `STUDY_GOAL.md` เพื่อคงทิศทางการพัฒนา บทเรียนปัจจุบันยังเป็นพื้นฐาน ไม่ใช่คอร์สเตรียมสอบครบถ้วน

## ตรวจฐานข้อมูลเกมในเครื่องพัฒนา

GitHub Actions ทดสอบ PostgreSQL 16 โดยจำลอง Auth schema เฉพาะในฐานข้อมูลทดสอบ รันทั้ง migration ซ้ำและตรวจ retries, daily XP, permission isolation, opt-in/withdrawal และอันดับ ไม่มีการรัน `test/auth-bootstrap.sql` ใน Supabase จริง Node tests ตรวจกลไกเกมและ OAuth ส่วน flow บัญชีจริงยังต้องทดสอบกับ Supabase ของคุณหลังรัน migration

## ระบบและค่าใช้จ่าย

- **GitHub Pages**: หน้าเว็บ static สำหรับ repository สาธารณะ ใช้แผนฟรีได้
- **Supabase Free**: PostgreSQL สำหรับประวัติ และ Supabase Auth สำหรับบัญชี/รหัสผ่าน ภายใต้โควตาแผนฟรี ตรวจเงื่อนไขปัจจุบันที่ https://supabase.com/pricing โครงการฟรีอาจถูกพักเมื่อไม่มีการใช้งาน และบริการอีเมลเริ่มต้นมีข้อจำกัด อาจต้องตั้ง SMTP ของคุณหากมีผู้ใช้มากขึ้น
- **ChatGPT**: ผู้เรียนคัดลอกบริบทไปใช้ใน ChatGPT ด้วยบัญชีของตนเอง เว็บไม่เข้าถึงโควตา Plus และไม่เรียก OpenAI API ผลการสนทนาไม่ถูกบันทึกกลับมายังเว็บ
- การปรับบทเรียนใช้กติกาจากคะแนน ไม่ใช่ AI: ทบทวนบทที่คะแนนล่าสุดต่ำกว่า 80% ก่อน จากนั้นเลือกบทที่ยังไม่เรียน หรือบทที่ฝึกน้อยที่สุด

ไม่มี secret key ฝังในหน้าเว็บ ใช้ publishable key สาธารณะและ Row Level Security ผู้เรียนอ่านได้เฉพาะโปรไฟล์และประวัติของตัวเอง ผู้ดูแล Supabase ยังมีสิทธิ์เข้าถึงข้อมูลตามบทบาทผู้ดูแล

## ทดลองในเครื่อง

ใช้ Node.js 24 ขึ้นไป ไม่ต้องติดตั้ง dependency

```sh
cd /workspace/fun-pali-learning
npm test
npm start
```

พอร์ตเริ่มต้น 4173 หรือกำหนด `PORT` ได้ โหมดทดลองทำงานโดยไม่ต้องมี Supabase และเก็บประวัติในเบราว์เซอร์เครื่องนั้นเท่านั้น โหมดทดลองไม่ใช่บัญชีออนไลน์ ไม่ควรใช้เพื่อเก็บประวัติสำคัญ

## ตั้งค่า Supabase ครั้งแรก

1. เข้าสู่ https://supabase.com/dashboard ด้วย GitHub สร้างองค์กร **Free** และ New Project เลือกภูมิภาคใกล้ผู้เรียน เช่น Singapore ตั้งรหัสผ่านฐานข้อมูลที่รัดกุม เก็บไว้ส่วนตัว ไม่ใส่ใน repository หรือแชต
2. เมื่อโครงการพร้อม เปิด **SQL Editor → New query** คัดลอกเนื้อหาทั้งหมดของ `supabase/schema.sql` แล้วกด **Run** สคริปต์รันซ้ำได้และไม่ลบประวัติเดิม
3. เปิดหน้าการเชื่อมต่อโครงการ/การตั้งค่า API เพื่อหา **Project URL** และ **publishable key** (`sb_publishable_...`) หรือ legacy **anon** key หากโครงการใช้รูปแบบเก่า ห้ามใช้ `service_role`, `sb_secret_...` หรือ database password
4. ใส่สองค่าลงใน `config.js`:

   ```js
   export const config = {
     supabaseUrl: 'https://YOUR_PROJECT_REF.supabase.co',
     supabasePublishableKey: 'YOUR_PUBLIC_PUBLISHABLE_KEY'
   };
   ```

5. เปิด **Authentication → URL Configuration** ตั้ง **Site URL** เป็น `https://jirayudech.github.io/fun-pali-learning/` และเพิ่ม URL เดียวกันใน **Redirect URLs** หากทดลองในเครื่องให้เพิ่ม URL ของเครื่องพัฒนาแยกด้วย ไม่ใช้ wildcard กว้างใน production
6. เปิดการสมัครผ่าน Email ใน **Authentication → Providers / Sign In** และเปิด **Confirm email** ตรวจอีเมลยืนยันการสมัคร บริการส่งอีเมลเริ่มต้นของ Supabase มีข้อจำกัดตามแผนปัจจุบัน หากส่งให้เพื่อนไม่ได้ให้ตั้ง custom SMTP ที่ตรวจสอบแล้วใน Authentication ก่อนเปิดรับผู้ใช้ทั่วไป ห้ามใส่รหัสผ่าน SMTP ลงในเว็บ
7. สมัครบัญชีทดสอบสองบัญชี ทำแบบฝึกหัดด้วยบัญชีแรก แล้วตรวจว่าบัญชีที่สองไม่เห็นประวัติแรก ปิดและเปิดเบราว์เซอร์ใหม่ด้วยบัญชีแรกเพื่อตรวจว่าประวัติยังอยู่

บัญชี Supabase Dashboard เป็นของผู้ดูแลเว็บ เพื่อนสมัครผ่านหน้าเว็บได้โดยไม่ต้องมีบัญชี Dashboard การเข้าสู่ Dashboard ด้วย ChatGPT ไม่ได้ให้เว็บใช้โควตา ChatGPT Plus

## ตั้งค่าเข้าสู่ระบบด้วย Google

ปุ่ม Google ใช้ Supabase OAuth แบบ PKCE บัญชีและประวัติผูกกับผู้ใช้ใน Supabase เช่นเดียวกับการเข้าสู่ระบบด้วยอีเมล ไม่ต้องรัน SQL เพิ่ม หากยังไม่เปิด provider ปุ่มจะแสดงข้อความแจ้งแทนการส่งผู้เรียนไปหน้าที่ใช้ไม่ได้

1. เปิด https://console.cloud.google.com/ สร้างหรือเลือกโครงการ แล้วเปิด **Google Auth Platform** ตั้ง Branding (ชื่อแอปและอีเมลติดต่อ) และ Audience เป็น **External** สำหรับผู้เรียนทั่วไป
2. ใน **Clients → Create client** เลือก **Web application** ตั้ง Authorized JavaScript origins เป็น `https://jirayudech.github.io`
3. ตั้ง Authorized redirect URIs เป็น `https://lufrqkqvtzzzbwkdnxql.supabase.co/auth/v1/callback` โดยใช้ callback ของ Supabase ไม่ใช่ URL หน้าเว็บ
4. ใน Supabase **Authentication → Sign In / Providers → Google** เปิด Google แล้วกรอก Client ID และ Client Secret ที่ได้รับจาก Google Cloud กด Save เก็บ Client Secret ใน Supabase เท่านั้น ห้ามใส่ใน `config.js` หรือ GitHub
5. คง Skip nonce checks และ Allow users without an email เป็นปิด ตั้ง Supabase **Authentication → URL Configuration** ให้ Site URL และ Redirect URLs มี `https://jirayudech.github.io/fun-pali-learning/` (รวม slash ท้าย) โหมดพัฒนาให้เพิ่ม URL ของเครื่องพัฒนาแยก
6. หาก Audience ยังเป็น Testing ให้เพิ่มอีเมลผู้ทดสอบใน Test users หากต้องการเปิดให้ผู้เรียนทั่วไป ให้เปลี่ยน Publishing status เป็น Production และทำขั้นตอนตรวจสอบที่ Google ขอ เว็บนี้ใช้ข้อมูลพื้นฐานสำหรับเข้าสู่ระบบเท่านั้น ไม่ขอสิทธิ์ Gmail/Drive
7. หลัง deployment ผ่าน เปิดเว็บ กด Google ยืนยันบัญชี ตรวจการกลับเข้าหน้าเรียน ทำแบบฝึกหัด ออกจากระบบและกลับเข้าด้วยบัญชีเดิมเพื่อดูประวัติ ห้ามสรุปว่าตั้งค่าสำเร็จจากปุ่มที่แสดงอย่างเดียว

การเข้าสู่ระบบ Google ไม่เชื่อมบัญชี ChatGPT หรือโควตา Plus และไม่เสียค่า OpenAI API

## เผยแพร่ GitHub Pages

1. ต้องเป็น repository สาธารณะสำหรับ GitHub Free และคุณต้องมีสิทธิ์จัดการ repository
2. Commit และ push โค้ดนี้รวม `config.js` ที่มีเฉพาะข้อมูลสาธารณะ ไปยัง `main`
3. ใน GitHub เปิด **Settings → Pages → Build and deployment → Source: GitHub Actions**
4. เปิด **Actions → Publish learning website → Run workflow** หรือ push อีกครั้งเพื่อเริ่ม deployment
5. รอ workflow ผ่านทั้ง build และ deploy แล้วเปิด URL ที่ GitHub แสดง โดย URL ที่คาดหมายคือ `https://jirayudech.github.io/fun-pali-learning/` URL นี้ยังไม่ยืนยันว่ามีเว็บจนกว่า deployment จะสำเร็จ
6. ตรวจทั้งหน้าเว็บ สมัคร/ยืนยันอีเมล/เข้าสู่ระบบ บันทึกผล อ่านประวัติ และออกจากระบบ ก่อนส่งลิงก์ให้เพื่อน

Workflow ส่งเฉพาะ `index.html`, `app.js`, `oauth.js`, `style.css`, `config.js`, `lessons.js`, `favicon.svg` ไม่ส่ง SQL หรือไฟล์ทดสอบขึ้นหน้าเว็บ การไม่มีค่า Supabase จะแสดงโหมดทดลองอย่างชัดเจนและปิดการสร้างบัญชี

## ฐานข้อมูลและสิทธิ์

- `profiles`: ชื่อที่แสดง เชื่อมกับ `auth.users` (รหัสผ่านอยู่ในระบบ Auth)
- `attempts`: บทเรียน คะแนน จำนวนข้อ และเวลา ไม่มีข้อความแชต ChatGPT
- `question_bank`: คำถามและเฉลยสำหรับตรวจบนฐานข้อมูล ปิดการอ่านผ่าน REST ของผู้เรียน
- `quiz_sessions`: แบบฝึกหัดที่ออกให้บัญชีนั้น อายุ 1 ชั่วโมง ส่งได้ครั้งเดียว
- `start_quiz` และ `submit_quiz`: RPC ใช้ผู้ใช้จาก JWT ตรวจสิทธิ์ ตรวจคำตอบ และบันทึกคะแนน ไม่รับคะแนนจาก client

เฉลยตัวอย่างใน `lessons.js` ใช้โหมดทดลองและอาจอ่านได้ใน source การทดสอบนี้มีไว้ฝึกเรียน ไม่ใช่ระบบสอบแข่งขัน บัญชีจริงยังตรวจคะแนนใน PostgreSQL

ประวัติบน dashboard แสดงไม่เกิน 1,000 ครั้งล่าสุด ประวัติเก่ากว่านั้นยังอยู่ในฐานข้อมูล โหมดทดลองเก็บประวัติใน localStorage ล้างได้ผ่านการล้างข้อมูลไซต์ บัญชีจริงเก็บ session token ใน localStorage ของเบราว์เซอร์; ใช้ออกจากระบบเมื่อใช้เครื่องร่วมกับผู้อื่น หน้าเว็บไม่มีสคริปต์ third-party

เวอร์ชันแรกยังไม่มีหน้าเปลี่ยน/กู้รหัสผ่านหรือลบบัญชีด้วยตนเอง ผู้ดูแลจัดการคำขอลบบัญชีใน Supabase Auth ได้ การลบบัญชีจะลบโปรไฟล์และประวัติที่ผูกไว้ด้วย `ON DELETE CASCADE` สำรองข้อมูลและทดสอบการกู้คืนก่อนใช้งานจริงระยะยาว
